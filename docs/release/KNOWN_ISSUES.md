# ClaimBridge — Known Issues & Sandbox Limitations

**Document Version:** 2.0 (Mission 016 Release Gate)  
**Classification:** Public Hackathon Disclosure  
**Date:** October 20, 2026  

---

## 1. Known Sandbox Behaviors & Acceptable Tradeoffs

| Issue ID | Description | Severity | Impact | Mitigation / Current Behavior | Hackathon Acceptability Justification |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **ISSUE-001** | Local Ollama Inference Latency on CPU | Low | Response time for AI investigations may range between 4–12 seconds on machines without GPU acceleration. | Frontend features responsive animated pending indicators with cancellation support. Background HTTP request timeout is bounded at 30 seconds. Core payout operations remain completely unaffected. | **Acceptable:** Satisfies the zero-budget constraint without forcing users to purchase paid cloud API keys or GPUs. |
| **ISSUE-002** | Polling Synchronization vs. Public Webhooks in Local Dev | Low | Status reconciliation for asynchronous PayPal batches requires clicking "Synchronize Status" or invoking the scheduled reconciliation endpoint when testing without public ingress (e.g. ngrok). | Durable `sender_batch_id` and item polling via `GET /v1/payments/payouts/{payout_batch_id}` ensures exact status reconciliation. | **Acceptable:** In local development without open public tunneling, manual or periodic polling is the standard recommended pattern. |
| **ISSUE-003** | Currency Constrained to USD in Initial Release | Low | Payout case creation and policy verification are restricted to currency `USD`. | Rust policy engine strictly validates `currency == "USD"`; non-USD requests are rejected fail-closed. | **Acceptable:** Meets Hackathon scope; multi-currency settlement can be unlocked in future milestones by configuring currency exchange tables. |
| **ISSUE-004** | Dual-Approval Role Isolation within Single Organization | Low | The dual-approval policy requires a distinct user ID (`CreatedByUserID != ApproverUserID`) to approve transactions > $250.00 USD. | In personal workspaces with only one operator, high-value payouts cannot be self-approved. The user must invite or register a second test officer account to approve high-value claims. Both accounts are pre-seeded in `demoOrg`. | **Acceptable:** This is the intended security invariant preventing fraudulent self-disbursement. |
| **ISSUE-005** | Production Host Hard Block | Informational | Configuring `PAYPAL_ENV=production` or `api-m.paypal.com` causes the application to immediately panic and terminate. | Intentional fail-safe: Prevents accidental real fund movement during testing or hackathon evaluation. | **Acceptable:** Mandatory hackathon safety invariant. |
| **ISSUE-006** | Live PayPal Sandbox Execution Blocked on Operator Credentials | Medium | Default `.env` template contains placeholders; live PayPal OAuth and payout dispatch cannot execute in public CI or unconfigured local environments. | The readiness tool (`services/api/cmd/readiness`) explicitly reports `[BLOCKED]` when credentials are unset. The offline demo track (Track 1) runs entirely with verified synthetic fixtures (`DEMO-W9821`). | **Acceptable:** Zero-secret public repository policy. Unblocking requires operator to supply personal PayPal Developer Sandbox keys in `.env`. |
| **ISSUE-007** | Live Local AI Inference Blocked on Running Ollama Daemon | Medium | Genuine model inference requires an active local Ollama daemon (`ollama serve`) with `llama3.2` model installed. | If the daemon is offline, the backend returns an honest HTTP 503 `AI_UNAVAILABLE` error without faking inference or corrupting payout state. Pre-seeded synthetic investigations are available for offline inspection. | **Acceptable:** Eliminates cloud API costs while maintaining zero-false-positive diagnostic honesty. |
| **ISSUE-008** | Hackathon Demo Video Recording File Upload Pending | Low | Complete demo script, shot list, and recording checklist are published in `docs/demo/`, but final video file is not yet uploaded to a video hosting platform. | Comprehensive 2-track demo script (`docs/demo/DEMO_SCRIPT.md`) and recording checklist (`docs/demo/RECORDING_CHECKLIST.md`) provide step-by-step reproduction instructions. | **Acceptable:** Video recording and upload is an external manual presentation action scheduled prior to final portal submission deadline. |
