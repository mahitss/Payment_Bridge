# ClaimBridge — Known Issues & Sandbox Limitations

**Document Version:** 3.1 (Mission 033.8.1A.4.1 Post-Merge Documentation Accuracy Corrections)
**Classification:** Public Hackathon Disclosure
**Date:** November 2, 2026

---

## 1. Known Sandbox Behaviors & Acceptable Tradeoffs

| Issue ID | Description | Severity | Impact | Mitigation / Current Behavior | Hackathon Acceptability Justification |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **ISSUE-001** | Local Ollama Inference Latency on CPU | Low | Response time for AI investigations on CPU without GPU acceleration was measured at approximately 60.6 seconds with `qwen3.5:4b` under a 4096 context window. | Frontend features responsive animated pending indicators with cancellation support. Background HTTP request timeout is configurable (`AI_REQUEST_TIMEOUT_SECONDS=120`, default 120s). Bounded inference options (`options.num_ctx: 4096`, `options.num_predict: 300`, `think: false`) prevent unbounded generation. Core payout operations remain completely decoupled and unaffected. | **Acceptable:** Satisfies the zero-budget constraint without forcing users to purchase paid cloud API keys or GPUs. Measured turnaround time is hardware-dependent (verified on single local CPU machine; not an SLA for arbitrary CPU hardware). |
| **ISSUE-002** | Polling Synchronization vs. Public Webhooks in Local Dev | Low | Status reconciliation for asynchronous PayPal batches requires clicking "Synchronize Status" or invoking the scheduled reconciliation endpoint when testing without public ingress (e.g. ngrok). | Durable `sender_batch_id` and item polling via `GET /v1/payments/payouts/{payout_batch_id}` ensures exact status reconciliation. | **Acceptable:** In local development without open public tunneling, manual or periodic polling is the standard recommended pattern. |
| **ISSUE-003** | Currency Constrained to USD in Initial Release | Low | Payout case creation and policy verification are restricted to currency `USD`. | Rust policy engine strictly validates `currency == "USD"`; non-USD requests are rejected fail-closed. | **Acceptable:** Meets Hackathon scope; multi-currency settlement can be unlocked in future milestones by configuring currency exchange tables. |
| **ISSUE-004** | Dual-Approval Role Isolation within Single Organization | Low | The dual-approval policy requires a distinct user ID (`CreatedByUserID != ApproverUserID`) to approve transactions > $250.00 USD. | In personal workspaces with only one operator, high-value payouts cannot be self-approved. The user must invite or register a second test officer account to approve high-value claims. Both accounts are pre-seeded in `demoOrg`. | **Acceptable:** This is the intended security invariant preventing fraudulent self-disbursement. |
| **ISSUE-005** | Production Host Hard Block | Informational | Configuring `PAYPAL_ENV=production` or `api-m.paypal.com` causes the application to immediately panic and terminate. | Intentional fail-safe: Prevents accidental real fund movement during testing or hackathon evaluation. | **Acceptable:** Mandatory hackathon safety invariant. |
| **ISSUE-006** | Live PayPal Sandbox Verification & External Boundaries | Medium | Default `.env` template contains placeholders; live PayPal OAuth, payout dispatch, and unclaimed cancellation cannot execute in public CI or unconfigured local environments. Furthermore, even with test credentials, genuine payout dispatch and genuine cancellation against live PayPal Sandbox endpoints remain unverified in the public repo runtime — all acceptance tests and CI suites run against high-fidelity deterministic test doubles (`services/api/internal/paypal`). In ambiguous provider outcomes, the operation is quarantined in `RECONCILIATION_REQUIRED` and blind retries are prevented, but provider-side execution status can remain unknown until reconciliation is completed (quarantine does not prove whether PayPal executed the payout). Zero real money was moved, disbursed, or cancelled during development, testing, or release auditing. | The readiness tool (`services/api/cmd/readiness`) explicitly reports `[BLOCKED]` when credentials are unset. The offline demo track (Track 1) runs entirely with verified synthetic fixtures (`DEMO-W9821`). Zero real money was moved or cancelled. | **Acceptable:** Zero-secret public repository policy. Unblocking requires operator to supply personal PayPal Developer Sandbox keys in `.env`. |
| **ISSUE-007** | Live Local AI Inference Gated by Running Ollama Daemon & Cloud AI Distinction | Medium | Genuine model inference is executed exclusively against a local Ollama daemon (`qwen3.5:4b` / `llama3.2`) on the operator's machine. Verified on a single local CPU development environment; this does not constitute a SLA or performance guarantee across arbitrary CPU hardware. Cloud AI APIs are intentionally not integrated in order to maintain zero external budget and prevent external data exfiltration. Automated CI continues to execute against deterministic mock test doubles without requiring an active Ollama daemon. | PR #4 merged native bounded `/api/chat` transport into `main`. Genuine local inference was verified with `qwen3.5:4b` on synthetic case `DEMO-W9821` (~60.6s, HTTP 201). If the daemon is offline, the backend returns an honest HTTP 503 `AI_UNAVAILABLE` error without faking inference or corrupting payout state. Pre-seeded synthetic investigations are available for offline evaluation. | **Acceptable:** Eliminates cloud API costs while maintaining zero-false-positive diagnostic honesty. |
| **ISSUE-008** | Hackathon Demo Video Recording File Upload Pending | Low | Complete demo script, shot list, and recording checklist are published in `docs/demo/`, but final video file is not yet uploaded to a video hosting platform. | Deterministic 1080p walkthrough recording artifact (`claimbridge-offline-demo-recording` / `claimbridge-demo-walkthrough.webm`, latest Main-Head Validation Run [40119075389](https://github.com/mahitss/Payment_Bridge/actions/runs/40119075389) Artifact ID `12569654956`, expiring November 7, 2026) is automatically built and verified in CI. Comprehensive 2-track demo script (`docs/demo/DEMO_SCRIPT.md`) and recording checklist (`docs/demo/RECORDING_CHECKLIST.md`) provide step-by-step reproduction instructions. | **Acceptable:** Video recording voiceover and public upload is an external manual presentation action scheduled prior to final portal submission deadline. |
| **ISSUE-009** | Dedicated PostgreSQL Test Database Requirement for Integration Tests | Low | Database-mutating integration tests require `TEST_DATABASE_URL` exclusively. `DATABASE_URL` is never used as a fallback. When `TEST_DATABASE_URL` is unset, tests skip cleanly in 0.00s. A manual sentinel experiment confirmed that with `TEST_DATABASE_URL` unset and an invalid `DATABASE_URL` value, tests skip cleanly without attempting a connection. | Developers running database integration tests must provide an isolated disposable test database URL via `TEST_DATABASE_URL`. Prevents unintended schema mutations or data loss on standard application databases. | **Acceptable:** Clean test isolation architecture preventing environment pollution. |
| **ISSUE-010** | Host OS DNS Resolution under Concurrent Stress on Windows | Low | During heavy concurrent database connections (e.g., 10 simultaneous goroutines in concurrency tests) connecting to external cloud-hosted Postgres endpoints from Windows, Windows default DNS caching may drop UDP queries (`no such host`). | Setting `$env:GODEBUG="netdns=go"` forces Go's internal DNS resolver and resolves all queries reliably. | **Acceptable:** Known OS-level UDP DNS quirk mitigated by Go runtime configuration flag. |
